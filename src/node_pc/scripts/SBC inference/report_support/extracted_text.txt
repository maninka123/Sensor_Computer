The deployment graph removes training work without changing the learned
enhancer
SCI trains with iterative stages and a self-calibration network, but its intended inference path uses one shared
illumination-estimation block. The standalone package keeps the three 3x3 convolutions used by Finetunemodel, folds
BatchNorm into the middle convolution, freezes the graph, uses channels-last tensors, performs safe arithmetic in place,
and runs under inference mode.

Scope and metric definitions
Cohort: one 600x400 RGB low-light image from the included LOL evaluation sample. Latency: wall-clock time for model
execution only; Pillow decode, tensor creation, and PNG encoding are excluded. Median, mean, and p95: calculated
from 100 measured runs after  warm-up runs. FPS:  divided by median milliseconds and therefore an implied
single-stream model-only rate, not camera-pipeline throughput. Speedup: eager median divided by optimized median
at the same thread count.

Measurement and validation methodology
The baseline reconstructs the repository's Finetunemodel enhancement path from Model_V3.pt. The optimized model
folds BatchNorm analytically, scripts and freezes a dynamic-resolution graph, and preserves channels-last memory
layout. Thread counts , , and  were evaluated independently. Numerical outputs were compared before -bit
conversion; saved PNGs were then compared per pixel. The packaged benchmark.py repeats the same method and
records platform, architecture, Python, PyTorch, affinity, resolution, run count, and backend results in JSON and CSV.

Limits and uncertainty
The reported latency is from a Windows x86 development machine and must not be presented as ROCK 5A
performance.
ROCK 5A results will vary with the Linux image, PyTorch and ONNX Runtime builds, CPU governor, thermal state,
memory pressure, and power delivery.
The package is CPU-only as requested; the RK3588S NPU and Mali GPU were not evaluated.
Model-only FPS excludes camera capture, image conversion, resizing, and output encoding.
ONNX and TorchScript can rank differently on Arm, so the faster backend must be selected using board
measurements.
Recommended ROCK 5A validation
1. Copy the complete SBC inference folder to a 64-bit ROCK 5A installation.
2. Run ./install_rock5a.sh, then confirm uname -m reports aarch64.
3. Run benchmark.py at 1, 2, and 4 threads with automatic A76-core affinity.
4. Select TorchScript or ONNX using median latency while checking p95 stability.
5. Repeat under the real camera resolution and sustained workload while monitoring temperature and throttling.
6. Keep full resolution by default; use --max-side only when the application explicitly accepts a resolution-speed
tradeoff.
