# Testing without sensor hardware

This document contains the simulation-only workflows. For physical device
networking and deployment, use the main [README](../README.md).

## Rosbag pipeline

Run the processing pipeline and ROSBridge in one sensor-computer terminal:

```bash
cd ~/catkin_ws_actual
ROSBAG=true ROSBRIDGE=true ./run_pipeline.sh
```

The controlled calibration input used for the performance report is
`2025-02-14-16-45-34_with.bag`. Replay it continuously in another terminal:

```bash
cd ~/catkin_ws_actual
rosbag play --loop --clock \
  /home/rock/Desktop/calibration_data/2025-02-14-16-45-34_with.bag
```

To loop every bag in another directory, use
`BAG_DIR=/path/to/bags ./run_rosbags.sh` instead.

## Timestamp checker

The timestamp checker compares rosbag time with LiDAR and camera header stamps
and recommends a `lidar_timestamp_shift` value:

```bash
python3 src/node_pc/scripts/timestamp_checker.py
```

The script currently reads `.bag` files from `Rosbag files/` at the repository
root.

## Docker test environment

The Compose rig provides a `surface` container at `10.20.0.10` with the ROS
Master and a `device` container at `10.20.0.21` with a synthetic point-cloud
pipeline. Run it from the repository root with Docker Desktop and WSL
integration enabled:

```bash
docker compose -f docker/docker-compose.yml up -d --build
docker compose -f docker/docker-compose.yml logs -f surface device
docker compose -f docker/docker-compose.yml ps
docker compose -f docker/docker-compose.yml down
```

The Windows host exposes the ROS Master at `http://localhost:11311` and
ROSBridge at `ws://localhost:9090`. Check the containers with:

```bash
docker compose -f docker/docker-compose.yml exec device \
  rosnode info /rosbridge_websocket
docker compose -f docker/docker-compose.yml exec surface \
  rostopic info /merged_colored_cloud
```

Native TCPROS additionally requires a Windows route to Docker/WSL's
`10.20.0.0/24` network because ROS advertises container addresses inside its
protocol. The bounded Docker TCP range `45200-45300` exists only to make port
publishing practical and must not be copied to physical hardware.

## Network emulation

The device container applies 5 ms delay, a 25 Mbit/s rate, and 0.1% loss by
default. Change or clear those test conditions with:

```bash
docker/shape_link.sh
docker/shape_link.sh --delay 12ms --rate 10mbit --loss 0.5%
docker/shape_link.sh clear
```

These settings test software behaviour; they do not model a production mine
network completely.

## Synthetic point-cloud publisher

For client development without live hardware:

```bash
set -a
source src/node_pc/config/network.env
set +a
source devel/setup.bash
roslaunch node_pc synthetic_pointcloud.launch rate:=10 point_count:=10000
```

The configurable arguments are `rate`, `point_count`, `source_frame_count`,
`topic`, and `frame_id`. The default topic is `/merged_colored_cloud`; all
points, colours, and timestamps generated by this launch are synthetic.
